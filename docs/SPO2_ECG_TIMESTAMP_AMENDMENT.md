# Record-level timestamp consistency amendment

The first paired-ECG execution stopped before duration-quality counts, rhythm exclusions, changes or effect models at the equality check between machine_measurements.ecg_time and the registry time. The publisher checksum had passed. An independent metadata-only SQL query found 676 matched subject/study records, all parseable, with 666 exact timestamp matches and 10 disagreements. Minute rounding does not explain these: the extrema of machine-minus-registry difference are −2,479,939,200 and +1,680,220,800 seconds. This is source disagreement, not a small clock-offset correction.

The original implementation aborted the entire analysis on any inconsistent record. This amendment instead rejects individual records that fail exact timestamp consistency, without attempting to decide which source is correct. All subject/study identifiers must still match; any identifier mismatch still aborts. Retain the original metadata-selected pair and person, and mark its measurement support unavailable if either member is rejected. Do not choose another ECG, change a time window, alter patient splits, relax a quality or model gate, or change an outcome definition.

Verify all 676 timestamp comparisons independently using native Python datetime parsing and SQL, and save aggregate consistency counts. Keep discordant patient metadata in the private Data database. The original failed execution remains documented. This is a source-validation amendment before any clinical outcome changes or model estimates; it cannot be used to claim biological confirmation or validated acquisition timing for the retained records.
